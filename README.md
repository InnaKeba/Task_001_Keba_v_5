# Практична робота 1: Варіант 5. Асистент для роботи з даними «Data Analyst»

## Опис проєкту
Цей проєкт реалізує повноцінну агентну систему для аналітики даних. Використано архітектуру Plan-and-Execute (планувальник → виконавець → перепланувальник) на базі LangGraph. Агент здатен декомпозувати складні аналітичні запити, виконувати SQL-подібні вибірки, рахувати статистику та виявляти аномалії.

## Реалізовані вимоги
- **Інструменти (Pydantic v2):** Створено 5 інструментів із суворою типізацією та `field_validator` (SQL-запит, статистика, аномалії, прогноз, видалення).
- **Plan-and-Execute:** Вузли графа обмінюються даними через `Structured Outputs` (схеми `Plan` та `ReplanDecision`).
- **Захисні механізми:** Впроваджено `max_steps` (ліміт ітерацій) та `timeout` для LLM, щоб уникнути зациклення.
- **Agentic RAG:** Підключено ChromaDB з 9 документами. Агент сам визначає, коли йому потрібна теоретична довідка.
- **Checkpointing:** Використано `SqliteSaver` для збереження графа станів.
- **Human-in-the-Loop:** Інструмент `delete_records` перериває граф (`interrupt`) і чекає на дозвіл оператора.
- **Тестування:** Написано 7 pytest-тестів (перевірка валідаторів схем та логіки інструментів).

## Відповіді на аналітичні питання
1. **Як Plan-and-Execute розкладає складний запит?** 
   Вузол `planner` формує масив ізольованих кроків. Далі `executor` бере кожен крок і підбирає інструменти лише для нього, що знижує когнітивне навантаження на модель.
2. **Чому delete_records потребує HITL?** 
   Запити на читання є безпечними. Видалення — це незворотна дія, яка фізично змінює стан бази, тому критично потребує людського запобіжника.
3. **Як structured outputs гарантують коректний формат?** 
   Вони примушують LLM повертати дані виключно у заздалегідь визначеній схемі, унеможливлюючи генерацію невалідного JSON або "зайвих роздумів".
4. **Зміна стратегії (replanner):** 
   Якщо інструмент повертає помилку, `replanner` аналізує це і замість виконання наступного кроку формує новий план (наприклад, звертається до іншої таблиці).
5. **Як timeout захищає від зависання?** 
   Гарантує, що граф перерве виконання і не витрачатиме ресурси, якщо сервер БД надто довго обробляє агрегацію або API провайдера не відповідає.

## Інструкція із запуску
1. Створити віртуальне середовище: `python -m venv venv`
2. Активувати: `.\venv\Scripts\activate` 
3. Встановити залежності: `pip install -r requirements.txt`
4. Додати `.env` з `OPENROUTER_API_KEY`
5. Запустити тести: `pytest test_agent.py -v`
6. Запустити базу знань: `python knowledge.py`
7. Запустити головного агента: `python main.py`
